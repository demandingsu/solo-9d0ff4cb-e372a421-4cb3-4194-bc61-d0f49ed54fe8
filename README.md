# CTD 下行剖面管理系统

海洋调查 CTD 投放数据的接收、下行剖面计算、版本化更正与发布下载，以及返航后采水瓶的
**瓶样交接单**生成与版本管理（Python + FastAPI + SQLite）。

## 业务规则

1. **上传与原始行保留**：CSV 必须含 `投放号,采样序号,深度,水温,盐度` 五列（也接受英文列名
   `cast_id, sample_no, depth, temperature, salinity`）。每个原始行按原始行号完整入库。
2. **整批拒收**：坏行（字段数不符、序号非整数、深度非法/为负、温盐非空但非有限数）或
   同一文件内采样序号重复（含异值冲突）→ 整批拒收（HTTP 422），库内数据不变。
   水温/盐度允许留空，空值按缺测处理。单文件仅限一个投放号。
3. **下行过滤**：按采样序号（原始行序）扫描，仅保留**深度首次严格超过此前最大深度**的读数；
   其余行标记为 `upcast`（回升行；深度相等记为重复深度）并给出排除理由。
4. **整米段剖面**：按 `floor(深度)` 分段给出温盐均值、读数计数与缺测段（覆盖范围内无保留行，
   或段内温盐全缺测）。
5. **整版更正**：同一投放号重传即生成新版本；旧版（无论是否发布过）立即置为 `superseded`
   且**停止现行下载**，旧剖面数据保留可追溯；新版预览并**确认发布**成功后才恢复供数。
6. **预览防陈旧**：只有投放的最新原始版允许发布；预览后若原始版已被替换，确认旧预览返回 409。
7. **并发一致性**：写事务使用 `BEGIN IMMEDIATE` + 条件 UPDATE，整条剖面（原始行、分段、
   排除行、缺测段）来自同一已提交原始版；失败整体回滚，不留半版、不产生错误现行结果。
8. **导出可追溯**：现行剖面 CSV 内含原始版本号、文件 sha256、每个保留读数的原始行号，
   以及全部排除行及理由。

### 瓶样交接单规则

9. **瓶样上传与整批拒收**：瓶样 CSV 必须含 `投放号,瓶号,采样序号（击发采样序号）,实验室盐度`
   四列（也接受英文列名 `cast_id, bottle_no, sample_no, lab_salinity`），并在表单中填写
   本批平行瓶盐度容差（非负数）。坏行（字段数不符、瓶号空、序号非整数/为负、盐度非有限数）、
   同文件瓶号重复、单文件多个投放号 → 整批拒收（HTTP 422），库内数据不变。
10. **按序号关联原始行**：以采样序号关联该投放**现行已发布原始版**的原始采样行，列出瓶号、
    原始深度、原始温盐读数；序号在原始版中不存在的瓶子给出无法关联原因且不可交付。
    **采瓶发生在回升段（含重复深度行）时仍直接采用原始行**，绝不套用下行整米均值，并在
    交接单中标注“回升段采瓶”及该原始行的排除说明。
11. **平行瓶资格**：同一采样序号的平行瓶取实验室盐度极差，极差 **> 本批容差** 时整组
    判为待核（`pending`），组内全部瓶子不进入可交付清单；极差恰好等于容差视为合格。
    更正其中一瓶须整批重传瓶样，同组资格随新批次整体重算。
12. **依据版本与停用规则**：每张交接单同时绑定一个已提交瓶样批次与一个已发布原始版
    （含两者的文件 sha256）。瓶样整批更正或投放原始版重传后，旧交接单**留存可追溯但
    立即停止现行下载**；原始新版确认发布后，通过“重新生成交接单”才能恢复现行单
    （原始版未发布时重新生成返回 409）。
13. **原子性**：瓶样批次与交接单的写入都在单个 `BEGIN IMMEDIATE` 事务内完成，交接单头与
    全部明细行同生共死，写入失败整体回滚，不留半张清单；全表同一投放至多一张现行单，
    且其瓶样批次与原始版均为当前有效版本。

## 启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

SQLite 数据保存在命名卷 `ctd-data`（容器内 `/data/ctd.db`）。

## 本地开发 / 无 Docker 环境

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
CTD_DATA_DIR=./data uvicorn app.main:app --reload --port 8000
pytest -q
```

## 页面操作

1. 选择 CSV → “上传并生成预览”；被拒收时页面列出全部坏行/冲突原因。
2. “投放列表”查看版本数与现行状态；点击“查看版本/预览”。
3. 预览整米段均值、缺测段、保留读数与被排除的回升行及理由。
4. 草稿版点“确认发布”；发布后“下载现行剖面”得到带原始版依据的 CSV。
5. 任何历史版本都可下载其原始 CSV 与查看剖面；非现行版本不能作为现行剖面下载。
6. 在“瓶样交接单”卡片选择瓶样 CSV、填写本批容差并上传；页面按序号关联现行已发布原始版，
   展示瓶号、原始深度/温盐、回升段采瓶标记、平行组盐度极差与待核/可交付/无法关联原因。
7. 瓶样重传即整批更正：旧批次与旧交接单立即停止现行下载（仍可查看与追溯下载）；
   原始版重传后先确认发布，再点“重新生成交接单”恢复现行下载。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/uploads` | multipart 上传 CSV，整批校验后生成草稿版与剖面 |
| GET | `/api/casts` | 投放列表（含现行版本） |
| GET | `/api/casts/{cast_id}/versions` | 版本历史 |
| GET | `/api/versions/{id}` | 版本详情：分段、缺测段、排除行、原始行 |
| POST | `/api/versions/{id}/publish` | 确认发布（非最新版返回 409） |
| GET | `/api/casts/{cast_id}/profile.csv` | 现行剖面下载（无现行版返回 409） |
| GET | `/api/versions/{id}/raw.csv` | 指定版本原始 CSV 重建下载 |
| POST | `/api/bottle-batches` | multipart 上传瓶样 CSV + 表单字段 `tolerance`，整批校验后建批次并生成交接单 |
| GET | `/api/casts/{cast_id}/bottle-batches` | 瓶样批次历史 |
| GET | `/api/casts/{cast_id}/handover-sheets` | 交接单历史（含现行状态、停用原因、计数） |
| GET | `/api/handover-sheets/{id}` | 交接单详情：逐瓶关联依据、回升标记、平行组资格与无法关联原因 |
| POST | `/api/casts/{cast_id}/handover-sheets/regenerate` | 原始新版发布后重新生成现行交接单（未发布返回 409） |
| GET | `/api/casts/{cast_id}/handover.csv` | 现行交接单下载（无现行单返回 409） |
| GET | `/api/handover-sheets/{id}/handover.csv` | 指定交接单下载（历史单标注“已停止现行下载”） |

`sample_data/cast001_bottles_v1.csv` 与 `cast001_bottles_v2_corrected.csv` 是配套
`cast001` 原始投放的瓶样示例：v1 中序号 6 平行瓶盐度差 0.14（容差 0.05 时整组待核），
v2 更正后极差 0.04 恢复可交付；序号 5、7 为回升/重复深度段采瓶，序号 99 无法关联。
